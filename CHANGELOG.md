# Changelog

## Unreleased

- The sniffer and honeypot are now **independent engines**: any of the four combinations (neither, either, both) is valid. Starting one no longer stops the other, and switching `mode` no longer stops what is running - `mode` now only selects which engine the unqualified start/stop acts on and which one `active` describes. `POST /api/runtime/` accepts `{"engines": {"sniffer": true, "honeypot": true}}` to set the running set outright and `{"engine": "...", "action": "..."}` to act on one; the snapshot gains `running_engines` and `concurrent`. The dashboard gets a switch per engine, and warns when both run that raw capture also sees the honeypot's own traffic, so those connections are stored twice under different interfaces.
- Added content decoders for 26 identified protocols (TLS, SSH, HTTP, NTP, SMB, LDAP, Kerberos, BGP, SIP, SSDP, QUIC, STUN, ISAKMP, WireGuard, VXLAN, LLDP, CDP, EAPOL, FTP/SMTP/POP3/IMAP/IRC/NNTP, Redis). Identification alone left a slice rendering as rows of "TCP a:1 -> b:2"; each decoder now yields a summary line and named fields. NTP mode 7 (monlist) is flagged explicitly as an amplification vector. Every decoder is bounds-checked and returns {} rather than raising, since the capture loop would otherwise record hostile traffic as an unparseable frame and lose it.
- Added a "Clear data" action to the dashboard header. It purges everything capture and the honeypot recorded - packets, tags, payloads, flows, domains, paths, sessions and the honeypot event database - then compacts the file on disk, while monitor definitions, honeypot listeners, rulesets, blacklists and the selected interfaces are left untouched. The confirmation dialog spells out both lists side by side, and warns when an engine is still running. Previously this only existed in Settings.
- **Security: removed the hard-coded default JWT signing secret.** `auth.py` fell back to the literal `sniff4hound-local-signing-key` when `SNIFF4HOUND_JWT_SECRET` was unset, and nothing in the packaging ever set it - so anyone holding a copy of the source (or the `.deb`) could mint a token that `authenticate_request()` accepted on any installation, without ever seeing the printed security code. The secret is now generated per installation with `secrets.token_hex(32)` and persisted `0600` as `SNIFF4HOUND_DATA_DIR/jwt_secret`; when that file cannot be written the process uses an ephemeral in-memory secret instead. Never a constant.
- **Security: the live security code no longer appears in the access log.** The frontend passes it in the `WS /ws/` handshake query string, and the access line printed the target verbatim, so every reconnect wrote a working credential to the console. `security_code`, `access_token`, `token` and `auth` are now redacted in both the request target and the `Referer`.
- **Security: the capture IPC token no longer travels on the command line.** `manage.py` spawned the privileged child as `sudo env SNIFF4HOUND_IPC_TOKEN=<64 hex> ...`, and `/proc/<pid>/cmdline` is world-readable, so every local user could read the shared secret of the capture channel. The token is now written to a `0600` file whose *path* is passed instead, and the file is removed as soon as the child has connected. `sniff4hound-capture`'s own sudo self-elevation does the same.
- **Security: failed authentication is now counted, logged and rate-limited.** Every `401` writes a `SECURITY AUTH-FAIL` line with the source address and reason, and counts against a per-IP sliding window with incremental backoff (`auth.AuthRateLimiter`); past the threshold the API answers `429` with `Retry-After` and the WebSocket handshake is closed with `4401`. The limiter is shared by the API, the WebSocket and `GET /api/auth/session`, so it cannot be dodged by switching transports. Configurable through `SNIFF4HOUND_AUTH_*`.
- **Security: hardened the JWT design.** Tokens now carry and validate `iss`, `aud`, `nbf`, `jti` and a key id derived from the secret and `JWT_KEY_VERSION`, `expires_in` is capped by `SNIFF4HOUND_JWT_MAX_TTL`, and `auth.revoke_jwt_id()` can invalidate a single token. Rotating the secret (or bumping the key version) invalidates every outstanding token at once.
- Added IOC export: `GET /api/export/{alerts,endpoints,flows,domains}?format=csv|json`, plus `GET /api/export/` describing the datasets and their columns. Rows are IOC-shaped (rule, severity, 5-tuple, domain, evidence, hit count, first/last seen) and built from the store listings the UI already uses; repeated monitor hits collapse into one indicator instead of one row per packet. The SOC and Investigate views offer the same download from an "Export" button.
- Added a per-interface counter of unparseable frames to `Sniffer.snapshot()`, the `stats_update` event and the dashboard. A frame the parser rejects was previously visible only as a line in the JSON log, so a burst of malformed/fuzzed traffic aimed at the sensor left no visible signal.
- Access log timestamps are now UTC in the same ISO-8601 format as every stored `created_at`, instead of local wall-clock time that could not be correlated with the events the request produced.
- A relative `SNIFF4HOUND_DB_PATH` now resolves under `SNIFF4HOUND_DATA_DIR` instead of the process cwd, so the runtime can no longer scatter a database into whatever directory it happened to be launched from (which is how a copy of `Sniff4Hound.db` ended up inside `frontend/`). Added `scripts/clean_artifacts.sh` to list and, on confirmation, remove artifacts older versions left in the tree.
- Corrected `ARCHITECTURE.md`, which claimed root was mandatory and that the launcher relaunches itself with `sudo` - the exact opposite of the code, which refuses to start as root and keeps the privilege in the `sniff4hound-capture` child. The auth section now also documents `X-Security-Code`, the `security_code` query parameter, the JWT hardening and the rate limiter.
- Fixed the running app answering `POST /api/runtime/` with "database is locked" whenever the test suite was run. `settings.DB_PATH` resolves to a fixed per-user path (`~/.local/share/sniff4hound/Sniff4Hound.db`) and `sniff4hound/app.py` opens it at module scope, so merely importing it - as `tests/test_smoke.py` does - attached a second writer to the live database. `tests/__init__.py` now points `SNIFF4HOUND_DATA_DIR` at a throwaway directory before any test module loads, and removes it afterwards (the suite used to leave a full 22 MB database behind on every run).
- Fixed ARP never appearing on the Protocols page, and host discovery going quiet, whenever the detection scope filter excluded "private". ARP carries IPv4 addresses in its own payload, so both endpoints classified as private and every frame was dropped from the pipeline - despite `_detection_muted`'s own docstring saying ARP must never be muted. Link-layer protocols (ARP/RARP/STP/LLC/LLDP/CDP) are now exempt: an IP-scope filter has no jurisdiction over a protocol that is not IP.
- Fixed the Protocols page rendering a card titled "Traffic" for every protocol without a frontend profile, so a capture carrying both IGMP and mDNS showed two identical cards. All 28 protocols the sniffer can emit now have their own profile, and the fallback derives its name from the protocol instead of a shared generic label. The SPA route table is generated from the same list (`utils.KNOWN_PROTOCOLS`), so `/protocols/mdns`, `/protocols/igmp` and even `/protocols/unknown` stop answering a bare 404 on refresh.
- Fixed banner and summary cells collapsing their table column. `overflow-wrap: anywhere` makes a cell's min-content width a single character, so the table's auto layout shrank the column to ~1ch and wrapped the banner one letter per line, stretching the row to hundreds of pixels. Those cells now have a definite width and clamp to two lines (7 views).
- Added TCP flag, ICMP type/code and ARP opcode criteria to the monitor/ruleset match language. Port scans, spoofed ARP replies and ICMP redirects carry no payload to search, so they could not be expressed at all before - the stealth scan variants in particular are deliberately low-volume, which the rate-based stateful detectors are the wrong tool for.
- Added 114 builtin monitors covering single-packet scan signatures (NULL/Xmas/FIN/Maimon/SYN-FIN/URG/all-flags), ICMP redirect/timestamp/address-mask probes, discovery protocols (mDNS, LLMNR, NBNS, SSDP, WS-Discovery, LLDP, CDP), directory and auth services (LDAP, Kerberos, TACACS+, MSRPC, WinRM, r-services, X11), databases and infrastructure (MySQL through etcd, Docker API, kubelet, JDWP), ICS/OT buses (S7comm, BACnet, IEC-104, OPC UA, EtherNet/IP, PROFINET and more), and the long tail of legacy/odd services (CHARGEN, finger, gopher, QOTD, IPMI, Teredo, PPTP...). Plus IGMP, GRE, ESP, AH, STP and LLC, which the sniffer decodes but nothing classified - IGMP alone was the single largest slice of a live capture while being entirely unclassified.
- The builtin monitor loader now merges `DEFAULT_MONITORS` with the packaged `default_monitors.json` instead of letting the file win outright, so a monitor added in code takes effect without regenerating a 25 MB JSON. The file still owns every id it defines.
- A TCP segment carrying no flag bits is now recorded as `NONE` rather than an empty string. `build_base_packet` and the honeypot's synthetic packets both default the field to empty, so "" could not mean "zero flags observed" without every undecoded packet looking like a NULL scan.
- Fixed a stray character left above the startup banner: `sudo`'s PAM prompt for the capture child ("Place your right index finger on the fingerprint reader") writes to /dev/tty and leaves its last line unterminated. The banner now erases the current line before drawing.
- Fixed the interactive console losing keystrokes, which made commands unusable: typing `/help` arrived as `[note] p`. The capture child was spawned with stdin inherited, and since sudo 1.9.14 `use_pty` is the default - so sudo runs the child on its own pty and relays this terminal into it for the whole session. Two readers on one tty means each keystroke goes to whichever reads first. The child is now spawned with `stdin=DEVNULL` (`sniff4hound/manage.py`); sudo's password/fingerprint prompt is unaffected, it talks to /dev/tty directly.
- Removed the blank line `terminal.emit()` wrote between a log line and the redrawn prompt, which double-spaced the entire console once the access log was busy.
- Bundled the RIR delegation catalog as `sniff4hound/data/ip_registry.json` (143k IPv4 and 69k IPv6 ranges from AFRINIC, APNIC, ARIN, LACNIC and RIPE NCC), with `scripts/build_ip_registry.py` to rebuild it. Public addresses now resolve to a country, registry and region without a system libGeoIP install, which previously left every public host unlocated and the map empty.
- Added IEEE 802.3 / LLC / SNAP decoding. The two bytes after the MAC addresses are a length field when <= 1500, not an EtherType; reading them as one filed every such frame as `unknown` with a misleading "EtherType 0x0006" summary. LLC frames now report their DSAP/SSAP/control and a named protocol, and SNAP frames hand off to the existing IPv4/IPv6/ARP parsers.
- Fixed console input being destroyed by log output: access-log lines printed from the HTTP threads landed in the middle of whatever was being typed, so entering `/help` arrived as several stray operator notes. Log lines now erase the prompt, print above it and redraw it with the partially typed command restored (`sniff4hound/terminal.py`).
- Fixed the detection scope filter not actually excluding anything: ruleset classification ran before the check so excluded traffic still came out tagged, and with "store all traffic" enabled it was persisted anyway because storage keyed off `not filter_enabled`. Excluded scopes now leave the pipeline entirely - unclassified, untagged, unanalysed and unstored - while still counting toward packets-seen.
- Fixed the Radar map anchoring every traffic arc on a fixed off-canvas pixel point, which rendered as a stray dot floating outside the map: with a site declared the arcs now start at the sensor's real position, and a pulsing marker there stands in for the private and loopback hosts that have no geolocation of their own.
- Added a declared sensor location (`GET`/`POST /api/settings/location`, plus a click-to-pick map in Settings). Private and loopback addresses, which have no geolocation of their own, are now plotted there instead of being dropped; public addresses keep their registry-derived location.
- The Radar map now opens in flat projection instead of the globe.
- Fixed `safe_float(value, None)` raising `TypeError` on an unparseable value: it fell through to `float(None)`, turning the "no value" sentinel used for optional coordinates into a crash.
- Made the operator chat two-way: `POST /api/chat/messages` plus a chat panel in the top bar, and anything posted from the dashboard is echoed onto the terminal. Added a `/chat` console command for the backlog.
- Added `/clear everything` and a "Stored data" panel in Settings that delete every row capture and the honeypot wrote (packets, tags, payloads, flows, domains, paths, sessions) and compact the database file. Monitor/listener definitions, blacklists and settings are never touched.
- Fixed `/clear monitors` in the console failing with "Unknown scope": the dashboard calls that half "monitors" while the store calls it "sniffer", and the command passed the name straight through.
- Added a Kibana-style time histogram above the Sniffer packet table.
- Simplified the access log to `date protocol method path ref loc status`, and escaped whitespace in caller-controlled fields so a crafted Referer cannot forge extra columns or fake a second log entry.
- Removed the empty "Sniffer Engine" and "Honeypot Engine" panels, and made toolbar buttons icon-only with tooltips.
- Added a detection scope filter: monitor and anomaly detection can now be muted for traffic that stays entirely within loopback, private or public addresses, from the Sniffer settings or `GET`/`POST /api/detection/scopes`. Capture is unaffected.
- Top bar: nav tabs are icon-only with tooltips and the bar is shorter, so the whole navigation fits without horizontal scrolling.
- Fixed the Sniffer/Honeypot runtime buttons rendering deformed: they passed `icon="mdi-..."` as a prop *and* an `<v-icon>` in the slot, so Vuetify drew the icon twice.
- Made `docs-pages` and `CodeQL` skip their publish/upload steps while the repository is private instead of failing the run; both resume automatically if it is made public.
- Fixed the interactive console failing to start with `NameError: name '_configure_console_autocomplete' is not defined`: the readline glue was left behind when the console moved to its own module. Added a test that actually starts the console thread, which is what would have caught it.
- Fixed the `docs-pages` workflow erroring on `Create Pages site failed: Resource not accessible by integration` by dropping `enablement: true`; GitHub Pages must be enabled once by hand instead.
- Rebuilt the interactive console as `sniff4hound/console.py`: a single declarative command registry that drives the help, the aliases and tab completion, so a command can no longer be executable but undocumented.
- Tab completion now covers command arguments, not just command names, including live values pulled from the running process (interfaces, monitor ids, honeypot listeners, busiest IPs).
- Added console commands `/restart`, `/interfaces`, `/monitors`, `/monitor`, `/listeners`, `/listener`, `/top`, `/alerts`, `/packets`, `/intel`, `/clear`, `/config` and `/version`, plus `/help <command>` detail. `/clear` requires an explicit `--yes`.
- Added an nginx-style `combined` access log to the web process, covering WebSocket handshakes (`101`) and closes; configurable via `SNIFF4HOUND_ACCESS_LOG` / `SNIFF4HOUND_ACCESS_LOG_COLOR`.
- Fixed `http_host` never being extracted: the `Host:` header regex anchored on `^` under `re.MULTILINE`, but the text it runs against has already been flattened to a single line, so every HTTP-derived domain was silently dropped.
- Fixed the `packets` domain-column migration test and the `no-useless-assignment` lint error that left the test suite and the frontend lint red.
- Published an unversioned `sniff4hound_latest.deb` alongside each versioned Debian asset, so `https://github.com/jorgelsc-dev/Sniff4Hound/releases/latest/download/sniff4hound_latest.deb` always serves the newest build from one permanent URL.
- Removed the WiFi 802.11 monitor-mode capture path (`sniff4hound/wifi.py`, `sniff4hound/netlink.py`, the `/api/wifi/monitor` endpoint, its Settings panel, and the eight `builtin-wifi-*` monitors); it never worked reliably enough to keep.
- Added explicit authorship, provenance, and repository protection documentation.
- Added CI enforcement for commit sign-off and PR provenance attestations.
- Clarified maintainer ownership, trademark/identity guidance, and protected review surfaces.
- Hardened frontend auth so query-string tokens only unlock `WS /ws/`, while HTTP requests still require headers.
- Kept the dashboard security code only in tab memory and cleared legacy browser storage artifacts.
- Updated the Debian packaging workflow and docs to publish `.deb` assets from `main` into GitHub Releases.
